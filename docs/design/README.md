## 給誰看

主要觀眾是評審與現場操作者。會議進行時，他們透過這個畫面快速理解主席**何時開口、為什麼忍住或受阻、目前處在哪個階段、誰講了多少、系統是否健康**。與會者本人不需要盯著畫面。

## 性格

克制、可信、果斷。介面像一份正在生成的會議紀錄加儀表板：資訊密度高但安靜。主席的介入要有權威感，但不能搶過真人會議本身。

## 視覺方向

- 暖沙色、紙張感的單一淺色主題，沒有深色模式。
- 主席是版面上**唯一使用強調色**（`--accent #A65D3F`）的角色，其餘一律沙系中性色。
- 髮線分隔，不用卡片邊框、不堆陰影；不用霓虹、漸層、玻璃擬態、裝飾性圖表，也不用通用 SaaS 的卡片牆。
- 字型：資料與逐字稿用中文無襯線（Noto Sans TC）；會議主題與主席話術用襯線（Noto Serif TC）以示區別；數字用等寬（JetBrains Mono，tabular-nums）。
- 設計基準 1440×900，右欄固定 380px，左欄吃剩餘寬度；瀏覽器版最小寬度 1200px。

## 設計原則

1. 先讓觀眾看懂主席「做了什麼、為什麼」，再呈現次要指標。
2. 開口、忍住、受阻與故障必須在語意上誠實，不用視覺包裝掩蓋失敗。
3. 主席是唯一的強調色；術語卡等輔助資訊維持次要地位。
4. 即時會議優先：畫面更新不能造成版面跳動、操作阻塞或關鍵訊息消失。
5. 操作必須可辨識、可聚焦、可用鍵盤完成；狀態不可只靠顏色傳達。

## 顯示層命名對照

畫面上的用語與程式內部值不同，內部值不動，只換顯示：

| 內部 | 顯示 |
|------|------|
| 發散期 / 呻吟區 / 收斂期 | 發想 / 拉鋸 / 決定 |
| 快路 · 規則計時 | 即時規則 |
| 慢路 · 每 5 秒評分 | AI 判斷（結果只有「開口／忍住」兩個詞；「想過但忍住」併進時間軸當淺色刻度） |
| 排入 / 開口中 | 準備開口 / 發言中 |
| 硬打斷 / 軟插入 | 直接打斷 / 等停頓再說 |
| 工程視角 / 應用視角 | 後台視角 / 會議視角 |
