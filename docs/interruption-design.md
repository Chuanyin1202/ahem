## 一、它的真實機制（讀 code 所得）

### 雙門檻，不是單一門檻

整個設計最聰明的地方：

```python
# thoughtful_agents/models/participant.py:229-231
im_threshold        = 3.5   # 開放發言權時，動機分 ≥3.5 就開口
system1_prob        = 0.3   # 沒過門檻時，丟直覺型發言的機率
interrupt_threshold = 4.0   # 輪次是別人的，要 ≥4.0 才敢打斷
```

先預測當下發言權歸屬（LLM 看最後 5 句，輸出「某人的名字」或 `"anyone"`），再分三條路：

| 發言權狀態 | 行為 |
|---|---|
| `"anyone"`（開放） | ≥3.5 才說；沒過還有 30% 機率丟一句 System-1 直覺型發言 |
| 輪到自己 | 無門檻，直接講最高分的念頭 |
| **輪到別人** | **≥4.0 才准打斷** ← **插嘴發生在這裡** |

### 動機評分的九個因子

LLM 打 1.0–5.0 分，5 分的定義寫得很直白：**「甚至會打斷正在說話的人」**。

**內在（我想說）**
- (a) 與自身長期記憶的相關性
- (b) 自己有資訊落差（疑問、好奇、困惑）
- (c) 能填補對話中的資訊落差（回答問題、補充、澄清）
- (d) 預期影響
- (e) 急迫性

**外在（該不該說）**
- (f) 與上一句的連貫性
- (g) 原創性（不重複已講過的）
- (h) **平衡（有沒有人被冷落）** ← 已是引導的雛形
- (i) **動態（別人是不是正想講）** ← 已是引導的雛形

### 沉默補償

```python
silence_factor = 1.01 ** turns_no_speak
rating *= silence_factor
```

底數 1.01 非常保守——10 輪沒講話才 ×1.105。**主席版本需要更激進。**

## 二、根本性問題：它是「參與者」不是「主席」

**這個框架是為「AI 當一個平等的參與者」設計的。**

看動機來源就知道：九因子有五個繞著「**我**對這個話題有沒有興趣、**我**有沒有疑問、**我**知不知道答案」轉。那是一個想融入對話的人。

> **主席的動機完全不同：**
> **不該因為「我對這個有興趣」而發言，該因為「這場會議偏了／卡住了／有人被冷落了」。**

## 三、三個必要改動

### 改動 1：評分準則整個換掉

把九因子從「我想不想說」換成「這場會議需不需要我說」。

- **保留**：(h) 平衡、(i) 動態 —— 本來就是引導判準
- **替換**：(a)(b)(c)(d) 這些以 agent 自我為中心的因子
- **新增**：偏離議題程度、共識成熟度、時間壓力、發言權分配失衡度、決策是否已可封板

#### 📌 改用三軸評分，「不介入」是獨立選項（2026-08-27，依據 [prior-art](./prior-art.md) 發現 1、1b、1c）

> ⚠️ 本節先前寫「LLM 天生過度熱衷插話」，讀完論文全文後**已修正**——
> 真實情況是**兩極崩壞**（有的模型幾乎每則都插話、有的幾乎不插話），詳見 prior-art 發現 1。

**改動：把單一動機分數換成三軸，三欄必填、彼此不互斥。**

```
Positive Reinforcement : 1-5   應該鼓勵／強化某種正在發生的行為
Negative Reinforcement : 1-5   應該抑制某種正在發生的行為
No Reinforcement Needed: 1-5   ← 獨立評分，不是「前兩者不夠高」的殘差
```

**為什麼「不介入」要獨立評分**：論文 Finding 3——決定何時「不要」介入很容易，
決定何時「該」介入很難。把不介入做成殘差，等於放棄了那個比較可靠的判斷。

#### 判定規則：改用三軸相對比較（2026-08-28 實測定案）

論文的原始門檻是「任一軸 ≥3 視為成立」，**但實測證明它在我們的場景會大量誤報**。

**實測發現**：誤報與正確判斷之間**只差 1 分**，而門檻 3 正好卡在最敏感的位置：

```
正確不介入： P2 / N1 / None4
誤報時    ： P3 / N1 / None3     ← positive 只多 1 分就跨過門檻
```

**改用相對比較**：

```
max(positive, negative) > none   → 介入
否則                              → 不介入
```

| 規則 | healthy 誤報率 | divergent 誤報率 |
|---|---|---|
| 門檻 ≥3（論文原版） | luna 60%、mini 20% | luna 0%、**mini 80%** |
| **相對比較** | **0%** | **0%** |

（2 模型 × 2 場景 × 5 次 ＝ 20 次測試，誤報全數消除；該介入場景的召回未受影響。）

**為什麼這樣改是對的**：`prior-art.md` 發現 1c 說「不介入」是獨立評分軸——
既然是獨立的軸，**它就該有否決權**，而不是只做個擺設。
論文原版的門檻設計讓 None 軸不影響最終判定，等於白填了。

**額外好處：對模型隨機性有魯棒性。** 同一場景同一參數重跑，positive 會在 2 和 3 之間跳動；
相對比較讓「模型有點想插話但也覺得不必要」的情況自然落在不介入側。

#### 📌 四條 Key Rules（論文原文，四份 prompt 共用的判準骨架）

| 原則 | 內容 |
|---|---|
| **Look at Intent and Impact** | 看發言者想做什麼、以及那些話會如何影響其他人 |
| **Use the Context** | 一定要看前後文。單獨看沒問題的話，放進脈絡可能是在升溫，反之亦然 |
| **Judge Behavior, Not Opinions** | 判斷絕不取決於你同不同意那個觀點。只看語氣、清晰度、建設性、對討論的影響 |
| **Remain Consistent** | 全程用同一套標準。不要猜測或過度詮釋，只用實際出現的內容 |

#### 📌 兩個防呆設計（論文自承的失誤，我們直接避開）

1. **強制對高分介入寫 rationale。** 論文把 rationale 設為選填，事後自承是最大失誤，
   「損失了一份極有價值的詮釋資源」。→ **我們對任一軸 >3 的介入強制記錄理由**，
   這剛好餵給 `development-plan.md` P0#7 的主持記錄。
2. **提醒模型「介入是有成本的」。** 論文指引原文：
   > *too many interventions on the moderator's part may result in an adverse reaction
   > from the participants; no one wants to be constantly told what to say or how to say it.*

   → 這句話直接放進 prompt。

#### 📌 近因假設：只看最近 N 則

論文只給標註者**最近 6 則發言**，理由是引導師本來就只能根據最後幾段做決定，
並引近因效果研究說明口語討論亦然。

→ **對我們是有利的簡化依據**：評分不需要餵入整場會議逐字稿，
只需最近幾則 ＋ 規則層提供的長期統計（發言時長、沉默時長）。**這同時大幅降低 token 成本。**

#### 📌 兩個已知的失敗模式（來自 PTFA 實作）

- 有時 **8 分鐘**才做出第一次介入，參與者早已產出一堆想法
- 有時**每個人講完就插話**，不讓參與者把想法發展完

→ 這正是改動 2（階段感知）要解的問題。別人已經替我們驗證了「沒有階段感知會怎麼死」。

### 改動 2：加上階段感知（Kaner Diamond）

框架完全沒有這個維度。**同一個念頭，在發散期該壓住、在收斂期該說。**
階段作為分數乘數：

| 階段 | 收斂／調解類介入 | 鼓勵發言類介入 | 推進／裁決類介入 |
|---|---|---|---|
| 發散期 | ×0.3 | ×1.5 | ×0.2 |
| **呻吟區** | **×0.2** ← 最重要 | ×1.0 | ×0.3 |
| 收斂期 | ×1.2 | ×0.5 | ×1.5 |

**呻吟區那條 ×0.2 是整個設計的靈魂**：別在群體正需要衝突的時候去和稀泥。這正是微軟 Facilitator（議程／計時器導向）做不到的事。

### 改動 3：打斷門檻從靜態變動態

現在寫死 4.0。主席的門檻應該是情境的函數：

```
基準門檻 4.0

有人連續講超過 90 秒     → 降到 1.0   （幾乎必打斷）
議程只剩 5 分鐘          → 降到 2.5
正在呻吟區               → 拉到 4.8   （幾乎不插手）
剛插過話 30 秒內         → +1.0       （別碎念）
```

## 四、核心：介入類型分類

不同介入類型的**偵測方式**與**急迫性**差很多，必須分開處理。

> ✅ **2026-08-28 實作驗證**：職責分工照這張表落地後，
> **慢路的類型判斷從錯變對**——`deadlock` 場景先前被六個模型全部誤判成「有人被冷落」，
> 在 prompt 的 type 選項移除快路負責的三種類型之後，正確答出「僵局」。
>
> **為了迴避弱點而做的分工，順帶把弱點本身修好了。**

### A 類：出聲介入（Real-Time / Foreground）

| 介入類型 | 怎麼偵測 | 延遲要求 | 打斷還是等停頓 |
|---|---|---|---|
| 發言超時 | **規則**（計時器） | 零 | **打斷** |
| 議程超時 | **規則**（時鐘） | 零 | 等停頓 |
| 有人被冷落 | **規則**（沉默時長） | 低 | 等停頓 |
| 事實錯誤 | LLM | 越快越好 | **打斷** |
| 重複已講過的 | LLM | 中 | **打斷**（省時間） |
| 離題 | LLM（語意距離） | 中 | 看嚴重度 |
| 假共識（太快沒異議） | LLM ＋ 階段 | 可等 | 等停頓 |
| 僵局（來回 N 輪無進展） | 規則 ＋ LLM | 可等 | 等停頓 |

### B 類：寫入介入（Read-**Write**）（2026-08-27 補上）

> ⚠️ **這一類原本整個漏掉了。**
> README 明寫「裁決的效力＝**說出來 ＋ 記錄下來**」，而「記錄下來」是本專案的核心差異化——
> 但它先前不在介入類型表上。（缺口由 Overhearing Survey 的 State 維度正交套用抓出。）

| 介入類型 | 觸發 | 出聲？ |
|---|---|---|
| **裁決寫入** | 僵局判定成立 | 出聲 ＋ 寫入 |
| 待辦登錄 | 出現行動項與負責人 | 通常不出聲 |
| 未決議題標記 | 議題延到下次 | 隨裁決一起 |
| 發言時間統計寫入 | 持續 | 不出聲 |

**與 A 類的本質差異**：A 類改變的是**會議當下的行為**，B 類改變的是**會議留下的產物**。
兩者的失敗代價也不同——A 類錯了很尷尬但可補救，**B 類錯了會被寫進記錄帶走**。

→ 直接餵給 `development-plan.md` P0#7 的「B. 主持記錄」。

### C 類：背景動作（Background，不出聲）（2026-08-27 補上）

> Overhearing Survey 定義的 Background＝agent 用 tool call 更新自己的世界模型、**不對使用者做任何提示**。

| 動作 | 用途 |
|---|---|
| **Kaner 階段判斷** | 持續更新目前在發散／呻吟區／收斂 |
| 查上次會議記錄、議程附件 | 支撐「這題上次就吵過」這類介入 |
| 計算發言佔比、沉默時長 | 快路的輸入 |
| 候選發言預先生成 | 慢路的核心機制 |

**兩個關鍵性質**：

1. **它是免費的**——不佔打斷預算、不消耗與會者注意力，卻直接決定慢路的評分品質
2. **階段判斷本來就該是持續跑的背景任務，而不是介入決策時現算**

> 💡 這對「Kaner 階段怎麼偵測」那個未解缺口是一個方向：
> 把它從「決策時的一個判斷」改成「背景持續維護的狀態」，問題性質就不同了。

### 仲裁與過期規則（2026-08-27 補上）

> Overhearing Survey §6.2 第五條原則：介面應優先處理**時效性高**的建議，
> 並**自動讓不再相關的過期建議失效**。

先前的設計有兩個洞：

1. **兩個介入同時觸發沒有仲裁規則**（例如「發言超時」與「離題」同時成立）
2. **慢路預先備好的候選發言沒有作廢機制**——5 秒前算好的介入，5 秒後可能已經不合時宜

需要補的規則：

| 規則 | 內容 |
|---|---|
| **優先序** | A 類規則型 > A 類 LLM 型 > B 類寫入。同類取分數高者 |
| **合併** | 同一目標對象的多個介入合併成一句話，不要連續說兩次 |
| **過期** | 候選發言帶存活時間；發言者換人、話題轉移、或超過 N 秒即作廢 |
| **冷卻** | 已在動態門檻中（剛插過話 30 秒內 +1.0） |

### 這張表藏著延遲問題的解法

**最需要立刻打斷的（發言超時）恰好是純規則、零延遲的；
需要 LLM 理解才判斷得出來的（離題、假共識、僵局）恰好可以等到停頓再說。**

所以架構分兩條路：

```
快路（規則層）：計時器、沉默時長、發言佔比
                → 毫秒級，直接觸發，不等 LLM

慢路（LLM 層） ：離題、重複、僵局、假共識
                → 背景持續評分，候選發言預先備好
                → 等停頓、或分數爆表時放出去
```

**「預先備好」是關鍵**：`thoughtful-agents` 本來就是平行持續產生想法的設計，剛好吻合。
決策時只讀已算好的分數，不現算 → **延遲只剩 TTS 的 ~150ms**。

## 五、打斷的執行方式：不模擬人類，走主席的路

> 2026-08-24 新增。這一節解掉「怎麼打斷得自然」——原本以為是死路。

### 為什麼「像人一樣打斷」做不到

| 難點 | 說明 |
|---|---|
| 語音學特徵 | 人類打斷會提高音量與音高、用特定短詞開頭、在**換氣點**切入。需要韻律（prosody）偵測，VAD 只能判斷「有沒有在講話」，給不了「這句要結束了」 |
| 精度 | 人類從決定打斷到出聲約 200ms 內。本專案鏈路即使決策零延遲，TTS 首字 150ms ＋ 播放路徑 ≈ 300–500ms |
| 重疊 | 真人打斷有 0.2–1 秒重疊然後一方讓步。AI 要嘛完全避免重疊（時機必錯過、死板），要嘛硬蓋上去（粗魯） |
| TTS 語氣 | 平穩的敘述語調插進激烈討論，像機器人念稿 |

### 出路：主席打斷跟參與者打斷是不同的社會行為

一般參與者要靠語音學技巧去「搶」發言權，因為他沒有權力。
**主席不用搶——他有制度性權力，打斷是被允許且被預期的。**

而真實世界的主席怎麼打斷？**敲槌、按鈴、指計時器。**

### 解法：提示音（earcon）先中斷，再說話

```
短促提示音  →  人自然停下  →  AI 開口
```

一招解掉四個難點：

| 原本的難點 | 提示音怎麼解掉 |
|---|---|
| 重疊處理 | 提示音沒有語意，蓋過去不影響理解 |
| 顯得粗魯 | 在會議情境下**完全自然**——那本來就是主席的工具 |
| 延遲 | 提示音零延遲播放，人停下來的 0.5–1 秒剛好夠 TTS 生成 |
| TTS 語氣 | 不需模擬插話語氣，開口時場已經是你的了 |

**比模擬人類打斷簡單一個數量級，而且在這個情境下反而更自然。**

### 分層執行

| 類型 | 對應介入（見第四節） | 執行方式 |
|---|---|---|
| **硬打斷** | 發言超時、事實錯誤 | 提示音 → 停頓 → 說話 |
| **軟插入** | 離題、僵局、假共識、有人被冷落 | 等停頓時直接說，不用提示音 |
| **視覺預告** | 全部 | 螢幕先亮起來，給人 1–2 秒預期 |

### 真正的風險不在這裡

打斷的**方式**可以用設計繞過，**判斷準不準不行**。
打斷得再優雅，只要打斷錯人、時機不對，那個介入就是失敗的。

→ **瓶頸在第一到四節那套評分，不在打斷的執行方式。**

## 六、待解問題

1. **回合制 vs 連續音訊流**
   框架是 turn-based，`predict_turn_taking_type` 用「最後 5 句」判斷發言權——在文字對話合理，但真實會議沒有明確 turn 邊界，人會 overlap。
   → 語音場景要改成 VAD ＋ 停頓偵測驅動，不是等一句話「結束」。

2. **發言權預測的成本**
